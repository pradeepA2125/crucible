# Durable native image support redesign

Date: 2026-10-09. Status: adopted direction; exact contract pending peer review before runtime edits. Branch: feature/image-support. No commits or branch switches. Preserve unrelated dirty files, especially the README landing-refresh plan.

## Problem and goals

Current tools/images.py returns a Data URL in ordinary ToolOutput text; API routes silently discard invalid/excess uploads and decode before bounds; controller stores images only in per-turn plan_context, not persisted user/history; normal _drain_main discards queued image options. Native Responses adds images after SessionInputs reconciliation and commits them on dynamic tails, accumulating copies across growing history. Memory compactor costs strings only. UI readers race thread changes/sends and recovery omits attachments.

Images must become native image parts at their originating durable user/tool history entry. Attachments survive follow-up, queue delivery (both paths), clarification/mode resume, reload, rewind and retry. A changed model must not pretend unsupported vision works. Dropped images must be explicitly unavailable to the model, while durable assets remain rereadable. No image bytes in prompt JSON, tool text, compaction summaries or logs.

## Exact contracts and ownership

Backend owns NEW `agentd/images.py` and asset/persistence/projection integration. Providers/UI owns serializers/capabilities/cache and all apps.

`ImageRef` is a JSON-safe dict with `asset_id` (SHA-256 lowercase hex of normalized bytes), `name`, `media_type`, `bytes`, `width`, `height`, `estimated_tokens`; no Data URL/path. Durable history entries store `image_refs: list[ImageRef]`. ChatMessage metadata stores `image_attachments: list[ImageRef]`. ToolOutput adds `image_refs` with an empty default, after existing fields for positional compatibility. Stable history entry identity and origin are preserved; queue user entries retrieve refs from persisted message metadata, not transient options. Rewind trims originating entries normally; assets retained for thread/workspace lifetime are not proof of current model access.

Immediately before provider inference, backend creates a fresh deep projection of history. Active projected entries retain `image_refs`; inactive refs are removed only from this transient projection and replaced with truthful text tombstones. A dedicated transport keyword `image_assets` maps asset_id to `{data_url, media_type, base64_data, bytes, width, height, estimated_tokens}` for active assets only. It is never inserted into user_payload/plan_context/history or serialized as prompt JSON. Durable history remains refs-only. Provider serializers join originating refs against image_assets and emit native parts at that origin BEFORE cache reconciliation. Tool images use native structured tool output where verified; otherwise pair textual tool output with an adjacent native user image entry owned by that same tool history origin. Preserve tool call/result correlation. Dedicated legacy `image_attachments` keyword remains compatibility only; production controller never repeats current images in dynamic tail. Provider code strips ref fields from textual JSON serialization. No provider owns filesystem reads or asset path resolution.

`ImageAssetStore(root: Path)` provides validated import of raw bytes/uploads and resolve(ref). Storage is workspace-private `.crucible/image-assets/<digest>.png` (or equivalent private store); write atomic immutable normalized content, restrictive directory/file permissions. Assets contain no paths/user-provided identifiers in filenames. Imports validate all attachments before storing messages. Missing/corrupt assets produce unavailable tombstones, not phantom visual access. Workspace read_image remains root-constrained (including symlinks) and supports rereading an asset by its durable ID within that workspace. Authentication and workspace isolation apply to API retrieval. A digest is identity, not authorization: tool asset reread is confined to the selected workspace-private store (same privilege as root-confined file reads), and HTTP preview additionally requires a reference in the requested thread. Deleting a thread revokes preview access immediately; immutable orphan assets are retained until explicit workspace cleanup (no automatic cross-thread deletion that could break another reference). Workspace removal/cleanup removes the private asset directory; this disk-retention policy is distinct from model context eviction. Secure asset storage/workspace reads currently require macOS/Linux descriptor-based no-follow primitives. Platforms lacking those primitives (including Windows) reject image operations explicitly; no unsafe path-based fallback is enabled. Windows support is deferred pending a reviewed reparse-point-safe implementation.

Preview endpoint: authenticated `GET /v1/chat/threads/{thread_id}/images/{asset_id}` returns normalized image bytes only when that thread's persisted message metadata/history references the asset. Wrong thread/workspace/unreferenced digest returns 404. Host HTTP client fetches with existing auth and passes a bounded Data URL to webview; webview never receives tokens or arbitrary local file paths. A metadata-only response remains valid if preview fails, with explicit unavailable rendering. Do not put preview bytes in model history.

## Validation and normalization policy

Add explicit Pillow dependency. Application limits (not universal provider limits): at most 8 images/upload; at most 8 MiB raw decoded bytes/image and 24 MiB aggregate/upload; encoded payload length bounded before base64 decode; at most 16 million decoded pixels/image and 40 million aggregate pixels/upload. Require strict base64 Data URL matching declared MIME/byte count; validate decoded image content against MIME, reject malformed/truncated images and decompression bombs before allocating full decoded buffers where possible. Bounded reads recheck actual byte length to avoid stat/read races. Accept PNG/JPEG/WebP/GIF/BMP/TIFF only when truly decoded as such; reject animated/multiframe inputs explicitly rather than silently losing temporal content. Normalize static images to RGB/RGBA PNG (provider-safe, preserve alpha), remove metadata, and enforce normalized per-image/aggregate bounds too. Zero images is valid; any invalid/excess image rejects the whole message request with actionable 400/413 and no persisted user message. Content-derived identities distinguish same filename/size different bytes. Aggregate limits and pixel checks are tested, not only documented.

## Retention, accounting and compaction

Estimate visual tokens conservatively as 1024 + 512 * ceil(width/512) * ceil(height/512), application heuristic not billed token measurement. Active context limits default to 8 unique assets, 24 MiB normalized bytes and 16384 estimated visual tokens, further bounded by available context headroom. Scan entries in reverse chronological order and refs within each entry in reverse index order. The newest occurrence owns the sole native image part and its cost; older identical refs become alias text pointing to that asset's newer visual occurrence, not additional image parts. Render retained origins in original chronological order. Available visual headroom is max(0, context_window - reserved_output_tokens - conservative_text_and_fixed_overhead_estimate), capped by 16384; absent trustworthy window/overhead use the conservative application cap. Drop any image exceeding remaining headroom (including newest), emit tombstone, then continue to smaller older candidates; do not silently send over-budget images. Admission validation errors and context-retention dropping are distinct. Every excluded ref gets `[Image <asset_id> (<name>) unavailable: image context budget / history compaction / missing asset. Do not claim to see it; reread using read_image with asset_id.]` in the relevant owned entry or surviving compaction summary. Durable refs stay recoverable; compaction eviction does not imply visual understanding of unseen pixels.

Compactor history trigger, hot selection and observed-token deltas include active visual estimates separately from content strings. An observed total already includes images: do not add the same visual cost twice. Track a projection revision fingerprint of active asset IDs and owning history positions plus unavailable/alias disposition. Invalidate observed baseline when that revision changes, including missing assets, dedup owner changes, budget changes or compaction; after compaction reproject and account again. Current controller admission reserves 28000 output tokens and a 16000-token fixed system/schema floor plus tool-definition/dynamic-plan estimates even before the first usage sample. Budget text includes the larger of ordinary projection and all-unavailable tombstones. ObservedPrompt pins the projected-history estimate from its measured request for later fixed-overhead subtraction; missing usage does not suppress projection-revision invalidation. Inactive/missing refs cost tombstone text only, not image tokens. Physical context metrics omit base64 character counts from text token estimate and report image_count/image_bytes/estimated_image_tokens separately. Changes to projection/retained assets must invalidate cached whole requests; old image bytes must actually disappear.

## UI lifecycle

Drafts have thread identity plus async-reader generation. Sending waits for completed validation/conversion and cannot race pending readers; switching thread/New chat cancels/discards stale callbacks. Explicit local validation errors; content identity not filename-size dedup. Draft previews have removal affordances. Every send path including slash fallback carries images. Failure restores original text AND attachments only to the originating thread/draft, without overwriting a newer draft. Optimistic sent metadata and persisted/reloaded messages render images using safe previews, with unavailable fallbacks. UI never reuses attachments in another thread implicitly.

## Follow-up: signed-in catalog compatibility and Retina bounds (request 69)

The prior implementation re-encoded at original dimensions and omitted native detail (provider default); it did not geometrically shrink Retina screenshots. The prior public-API finite allowlist incorrectly applied to signed-in plan models.

For ChatGPT-plan only, factory injects an account/registration-bound async catalog lookup using the same bearer as inference. Preserve optional input modality metadata: explicit image permits; explicit text-only or empty modalities denies; absent modality on a visible account-listed model permits an **optimistic native-image attempt**, not a claim of verified vision. Failed catalog lookup and unlisted models deny actionably; no slug prefix guessing. Refresh on credential/account identity change and model switches; no cross-registration positive cache. Public API/custom endpoint policy remains separate. Server image rejection must surface actual actionable error without silently dropping images or retrying text-only. gpt-6.1-sol, gpt-5.6-luna and future visible account slugs are test fixtures, not a replacement static list. Provider owner researches https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference.md (account catalog authority; no modality guarantee).

Normalization v2 is shared ingress and durable resolution policy: validate original bytes/pixels first, then use aspect-preserving LANCZOS downscaling, never upscale, maximum longest edge 2048 and maximum 4,000,000 transmitted pixels. Encode optimized lossless RGB/RGBA PNG; if encoded PNG exceeds 2 MiB transport target, progressively reduce dimensions (0.85 factor) until bounded, with minimum longest edge 512 before explicit rejection. Application limits are not guaranteed provider billing limits or lossless text readability. PNG preserves screenshot edges; bounded scaling may lose tiny text, so report dimensions and allow the user to attach a crop. Responses explicitly selects researched high detail for text readability, not auto/low; other native serializers retain provider-appropriate image blocks.

Image refs/map add optional original_width/original_height/original_bytes and normalization_version=2; existing width/height/bytes/estimated_tokens always describe **transmitted** normalized pixels. Preview serves transmitted raster, not original raw upload. Originals are not newly persisted solely for previews. Existing legacy digest assets remain immutable/readable: resolve/read preview computes deterministic v2 derivative from validated old bytes without changing original digest identity or overwriting its file. Map may expose transmitted digest separately; ownership remains original asset_id. ref_for_asset returns refs for a durable derivative when explicit reread imports it. Repeated resolve must be deterministic; no digest mismatch rejection merely because normalization policy changed. Original metadata fallback for legacy refs describes stored pre-v2 bytes. Projection must update dimensions from trusted resolved map before token costing, not stale durable ref dimensions.

Acceptance adds synthetic Retina screenshot fixtures with concrete before/after dimensions/bytes, actual decode/PNG measurements, aspect/no-upscale/idempotency/byte bounds, high-contrast text-edge preservation and legacy derivative preview consistency. Whole outgoing real-owner plan-route requests decode transmitted images, assert explicit detail and bounded dimensions, no accumulation across history growth, and actual disappearance on budget drop/compaction. Test catalog absent/explicit text-only/errors/new slug/account/model switch and server rejection. No claim of reading the user's live account or successful live inference without evidence.

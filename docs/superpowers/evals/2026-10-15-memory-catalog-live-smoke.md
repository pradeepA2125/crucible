## Progress signal correction

The owner observed that large outputs looked stuck. Inspection found two concrete gaps:

- `OpenAIJsonTransport._stream_response` counted `response.output_text.delta` but omitted `response.function_call_arguments.delta`. Native ChatGPT actions carry edits/reports in those arguments, leaving counts static until completion.
- The agent view reducer ignored token-progress events, and the shared child transcript omitted its live activity line unless a tool was pending.

Native argument deltas now feed the existing throttled output ticker without changing parsing, execution, approvals or exposing argument text as reasoning. Agent views retain ephemeral counts and show their live line between tools. Main-chat counts remain only in the pinned footer; a briefly duplicated transcript counter was removed at the owner's request. An integration regression asserts only one main counter while child views retain theirs. Counts are estimates while streaming, not percent completion or proof the model is doing useful work.

Verification: 66 transport/ticker tests, 136 UI/layout checks and webview typechecking passed for the initial fix; focused ruff passed. Following the duplicate-counter correction, 30 focused main/agent transcript tests passed. The backend restart's health HMAC matched its token, PID and workspace; its token was not printed. The UI-only follow-up was installed without restarting the active landing task.

Live landing SSE now contains hundreds of incrementing approximate output events before a native action completes.

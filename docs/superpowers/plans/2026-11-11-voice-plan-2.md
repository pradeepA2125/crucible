# Voice Plan 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interruptions that pause and resume (echo-aware on built-in speakers), a faster ChatGPT voice model with a per-provider setting, voice exchanges saved in the chat with "do it" context, and project words for Whisper.

**Architecture:** Renderer (`webview-ui/src/desktop/voice/`) gains a separate output audio context that can pause/resume, and an `EchoGate` that tells the user's voice from the reply's own echo. The backend voice agent picks gpt-6-luna on the ChatGPT plan, accepts a per-request model override, persists voice exchanges and narration as marked chat messages that every coding-agent and approval reader ignores, and adds a `basis` field so work requests carry only the exchange they rest on. The desktop host passes project words from a new backend route into the Whisper helper at session start.

**Tech Stack:** TypeScript/React (webview, Electron host), Python/FastAPI (agentd), C++ (whisper.cpp helper), vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-11-voice-plan-2-design.md`

## Review Focus

1. A cough during a reply on built-in speakers: the reply pauses then resumes from the same audio position, and never stops for good (Task 3: `a cough over a reply pauses it and resumes from the same point`).
2. The reply's own voice coming back through laptop speakers never pauses it (Task 2: `echo alone never counts as the user`; Task 3: `the reply's own echo never pauses it`).
3. A Whisper mishearing in a saved voice message never authorizes a command (Task 7: `test_voice_messages_are_not_permission_for_the_auto_judge`).

5. A voice message written while no turn runs appears without a reload, and one written mid-turn does not disturb the streaming answer (Task 8: `a voice message saved between turns appears on the next live poll`).

### Task 2: Echo gate

**Files:**
- Create: `apps/vscode-extension/webview-ui/src/desktop/voice/echoGate.ts`
- Test: `apps/vscode-extension/webview-ui/src/desktop/voice/echoGate.test.ts`

**Interfaces:**
- Produces: `class EchoGate { observe(micRms: number, outputRms: number, speechProb: number): boolean; reset(): void }` — `observe` is called once per 20 ms frame while output plays and returns true once the user's voice is established. Constants: `ECHO_MARGIN = 3`, `ECHO_WINDOW_FRAMES = 150`, `USER_ONSET_FRAMES = 4`, `VAD_USER = 0.5`.
- Algorithm: coupling = 20th percentile of `micRms / outputRms` over the last `ECHO_WINDOW_FRAMES` frames with `outputRms > 0.001`; a frame is "user" when `speechProb >= VAD_USER` and `micRms >= ECHO_MARGIN × coupling × outputRms + 0.004`; true after `USER_ONSET_FRAMES` consecutive user frames. With `outputRms <= 0.001` (headphones, gaps) only the probability rule applies.

- [ ] **Step 1: Write the failing tests**

```ts
it("echo alone never counts as the user", () => {
  const gate = new EchoGate(); // laptop speakers: mic hears 30% of output, Silero says speech
  for (let i = 0; i < 500; i += 1) expect(gate.observe(0.3 * 0.1, 0.1, 0.95)).toBe(false);
});
it("the user's voice over the echo is recognised within 80 ms", () => {
  const gate = new EchoGate();
  for (let i = 0; i < 150; i += 1) gate.observe(0.03, 0.1, 0.95);
  const hits = Array.from({ length: 4 }, () => gate.observe(0.03 + 0.08, 0.1, 0.95));
  expect(hits).toEqual([false, false, false, true]);
});
it("with headphones (no echo) speech is recognised from the probability", () => {
  const gate = new EchoGate();
  expect(Array.from({ length: 4 }, () => gate.observe(0.05, 0, 0.9)).at(-1)).toBe(true);
});
it("a loud non-voice sound is not the user", () => {
  const gate = new EchoGate();
  for (let i = 0; i < 20; i += 1) expect(gate.observe(0.2, 0.1, 0.1)).toBe(false);
});
```
